# 배치 추론

이 문서는 벤더 런타임에서 프레임워크의 논리 배치를 실행하는 방식을 기록한다.
벤더별 구현과 검증 범위는 아래 절에 추가한다.

## DeepX DX-M1: 동기 SDK 배치

### 변경한 경로

`DeepXRuntime.run()`은 입력 텐서의 선두 차원에서 논리 배치 크기 `B`를
확인한다. `B=1`은 기존 동기 `InferenceEngine.run()` 또는 다중 입력 모델의
`run_multi_input()` 경로를 사용한다. `B>1`은 `_run_sdk_batch()`에서
`B`개의 샘플로 입력을 나누고 **DX-RT `InferenceEngine.run()`을 한 번**
호출한다. 프레임워크 내부에서 배치 1 호출을 반복하던 `microbatch` 모드와
해당 타깃 옵션은 제거했다. 이 변경은 동기 `run()` 경로에만 적용된다.

DX-RT Python SDK의 배치 호출에는 샘플별 출력 버퍼가 필요하다. 런타임은
`get_output_size()`로 모델의 샘플당 출력 바이트 수를 얻어 각 샘플에
`uint8` 버퍼를 하나씩 할당한 다음 `run(samples, output_buffers=buffers)`로
전달한다. 단일 입력 모델에서는 샘플과 버퍼를 각각 평탄한 리스트로,
다중 입력 모델에서는 각각 샘플별 중첩 리스트로 전달한다. SDK가 반환한
샘플 수와 샘플별 출력 텐서 수를 확인하고, 기존 출력 정규화 경로에서
출력 이름별 `(B, ...)` 배열로 합친다.

따라서 `.dxnn`의 입력 ABI가 배치 1로 고정되어 있어도 프레임워크의
`--batch-size`는 DX-RT SDK 호출에 여러 샘플을 묶을 수 있다. 이것은
DXNN 그래프의 물리적 배치 차원을 바꾸거나 재컴파일하는 작업이 아니다.

### 실기기 확인

2026-11-20에 Jetson에 연결된 DX-M1, DX-RT Python `dx_engine 3.4.0`에서
`origin/main`(`728e701`) 기반 패치를 검증했다. ResNet50, YOLOv5m,
YOLOv8s-pose의 동일한 artifact 묶음으로 각 모델을 배치
`1, 2, 4, 6, 8, 10, 12, 14, 16`에서 실행했다. 총 **27/27 호출**이
성공했고, 모든 샘플의 모든 출력 텐서는 동일한 입력을 배치 1로 실행한
결과와 일치했다(최대 절대 차이 `0.0`). ResNet50은 출력 1개,
YOLOv5m은 3개, YOLOv8s-pose는 9개를 확인했다.

검증은 결정적 합성 `float32` 입력과 실제 DXNN을 사용한
`DeepXRuntime.run()` 호출이다. 데이터로더·전처리·디코더·평가기를
포함한 전체 E2E 실행, 데이터셋 정확도, 반복 측정 성능은 이 결과에
포함되지 않는다. native async의 배치 호출도 이 패치의 범위가 아니다.
